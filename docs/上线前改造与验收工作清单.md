## 四、工作包 2：让四层记忆保存事实、更新事实、使用事实

### 根因

当前 `memory/layers/WorkingMemory.py` 的 `previous_question` 主要返回上一轮实体名称。`GroundedAnswerService.generate()` 收到了 `memory`，但生成请求主要使用当前问题和改写问题，长期偏好仅影响简洁程度。

所以 PostgreSQL 和 Redis 即使工作正常，也不能自动让模型知道“一个月”“怀孕十周”“这次问的是母亲”。**存了历史和正确使用历史是两项不同能力。**

### 需要实现的结构

在现有 `memory/entity`、`memory/service`、`memory/layers` 下增加或扩展类，不增加第二套会话系统。建议添加 `ConversationState` 与 `ContextResolver`；这些是待新增的名称，不是现有实现。

当前会话状态至少包含：

| 字段 | 内容 | 更新原则 |
|---|---|---|
| `subject_id` | 当前描述对象：自己、母亲、孩子等 | 换人时切换；不把自述年龄套给家人 |
| `symptoms` | 表现、部位、程度 | 每条区分肯定、否定、不确定 |
| `timeline` | 起始时间、持续时长、进展 | 区分原有与新发生；保留变化 |
| `measurements` | 血压等数值、单位、测量情境与时间 | 保留历史读数，不只存最新数字 |
| `constraints` | 用户明确给出的年龄、孕期、哺乳等 | 绑定患者，不由模型推断 |
| `medications` | 用户自述药名和用法 | 不能自动转为推荐处方 |
| `tests` | 用户描述的检查结果 | 标记为用户自述，未经验证 |
| `concerns` | 用户担心的疾病或问题 | 只是担忧，不是已确诊疾病 |
| `pending_questions` | 系统已问、用户尚未回答的信息 | 用户补充后关闭，避免反复追问 |
| `provenance` | 来源轮次、原始片段、事实状态 | 每条可追溯；更正后旧值标为被替代 |

- [ ] L1 持有本轮选中的事实；L2 缓存当前会话状态和版本；L3 持久保存事件及可重建状态；L4 只保存明确确认的长期偏好或背景。
- [ ] 使用本轮与前轮共同判断是在补充、追问、纠正还是换话题；不能仅靠句首“那／这个／是的”决定。
- [ ] 对“我没有发烧”“不是我，是我妈”“检查正常”保留否定与纠正语义，不能只把其中的“发烧”“甲状腺”拿去检索。
- [ ] 只把解决本轮问题需要的事实传给生成与审核，两者必须看到一致的上下文。不得把完整账户历史无差别发送给外部模型。
- [ ] 将会话事实标记为用户提供的信息，将医学证据标记为来源资料；会话事实不能被当成医学引用。
- [ ] 事实回忆问题可直接从会话状态回答，例如“我刚才说多久了？”不需要重新查医学知识库。
- [ ] “甲亢会不会导致我这样”不能写入“用户患甲亢”；检索到疾病也不能自动提升为用户诊断。
- [ ] 模型抽取结果经过字段、类型、原文片段和允许状态转换验证，不能让其自行写入长期记忆。

### 必须通过的多轮验收

1. “睡不着一个月”→“下午五点喝咖啡”→“和这个有关系吗”：结合睡眠背景回答；随后问时长能答出一个月。
2. “怀孕十周、嗓子疼”→“布洛芬吃一片行不行”：仍带孕期约束，不批准个人用药。
3. “担心甲亢”→“抽血正常”：回应原担忧和检查局限，不跳去介绍甲状腺肿大。
4. “自己失眠”→“改问母亲膝痛”→“说的是谁”：明确母亲，不能混用自己的信息。
5. 系统问年龄、时长，用户全部补充后，不再原样问同一组问题。
6. 清空或失效该测试会话的缓存后，可从 PostgreSQL 重建同样的状态；另外一个用户和新会话读不到这些状态。

**完成标准：** 测试中的关键身份、孕期、否定和纠正信息全部正确；状态有来源轮次；后端服务链路测试通过，不能用直接传入 `previous_question="甲亢"` 代替多轮验收。

### 再修理解与召回

- [ ] 文档的单个 `facet` 标签不能决定其全部用途。允许有文本依据的多分面匹配，例如概述中确实写了并发症；不要简单把所有概述都判为所有分面。
- [ ] 图谱关系只能作关联或检索线索，不能把一条边直接解释成因果、用药许可或诊断。
- [ ] 权威模式保留核验来源要求；探索模式保留待复核资料，但两者均共享风险分流和引用检查。

### 参数实验怎么做

当前关键设置包括 `retrieval_k=16`、`context_k=6`、最多 3 轮和 6 次模型调用；证据相关度门槛存在 `0.48` 固定值，最终生成还会进一步挑选最多 4 份证据。必须同时检查这些环节，单独扩大 Dense 的 k 不一定改变最终答案。

1. 固定数据、模型和题集，先保存现状。
2. 先比较 `retrieval_k` 的 16／24／32，其他参数不变；再单独比较 `context_k` 的 6／8。
3. 每组同时报告相关证据召回、无关证据混入、最终答案质量、P95 耗时和模型调用数。
4. 来源风险、人群与证据资格作为独立检查，不用单一相似度分数代替。
5. 分数不是医学正确概率，也不宜直接跨模型比较；阈值选择必须用标注的相关／不相关样本验证。
6. 选开发集上稳定的配置，再在未用于调参的题集确认。失败时回到阶段记录定位，不反复降低阈值直到能答。

**完成标准：** 能解释每个失败案例在哪里失去可用证据；常见口语问法的正确资料能够进入最终上下文，且无关内容没有因放宽参数明显增加。

- [x] 将审核结果拆成切题、事实支持、人群适用、危险信号处理和覆盖不足，保存明确失败原因。

- [ ] 当一部分问题有充分依据时，可回答那部分并说明未知项；不得将已经确认的高风险求助提示一起隐藏。

### 9 次生成失败怎么排查

先读取 `reports/industrial-dialogues.json` 中失败轮次的 `result.trace`、`warnings` 和来源。逐项登记：失败阶段、异常类型、两次尝试的审核理由、当时证据是否足够。先解决占比最高的原因，再比较同题结果。

**完成标准：** 实测中不再用大片拒答掩盖问答不可用；有资料的普通问题能稳定生成有帮助的回答；不能只凭模型自评或“引用编号存在”判为正确。

### 每轮怎么打分

由审阅者阅读用户当前问题、必要的前文、实际答案和引用片段，分别标注：

| 维度 | 合格条件 |
|---|---|
| 切题 | 回答当前真正的问题，或提出必要澄清 |
| 上下文 | 正确使用患者身份、时长、否定和更正，不编造历史 |
| 有用 | 给出能帮助理解或行动的信息，不是泛泛定义或重复拒答 |
| 依据 | 关键医学主张得到引用支持；引用没有冒充、错配或过度推广 |
| 风险 | 不漏明确危险求助，不确定性合适，不做个人处方 |
| 表达 | 清楚、自然、适量，不机械拼接、不重复前言 |

每项记 0／1／2：0 为不合格，1 为部分满足，2 为满足。**身份、风险或关键医学事实出现严重错误，直接判该场景失败，不能用总分平均抵消。**

拒答只有在确实超范围、关键资料不可得或属于个人决策时才可能合格；模型超时和上下文丢失导致的拒答是产品失败。澄清若重复已回答的问题，同样不合格。

- [ ] 全部风险专项及高风险输出由有资质医学人员评审；若没有这项资源，不把产品发布为面向患者的症状咨询工具。
- [ ] 普通知识也需要覆盖所承诺病种的医学审阅；至少对一部分样本双人独立打分，记录分歧并裁决。
- [ ] 报告各题组、各模式的表现与置信区间；不把单次观察到零错误解释为真实错误率为零。
- [ ] 对随机性敏感的关键用例重复执行至少 3 次，展示所有结果，不只保留最好的一次。
