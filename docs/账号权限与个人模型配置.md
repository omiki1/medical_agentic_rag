## 每个用户填写自己的模型

1. 登录，点击侧栏底部「模型设置」。
2. 选择模型服务商，再从联动下拉框选择模型并填写 API Key。接口地址由系统填写，用户不需要手动输入。
3. 保存后返回「知识问答」。保存不会自动发起付费调用，也不代表接口可用性已验证。
4. 该账户的回答生成、Agent 规划与答案校验均使用自己的配置。没有配置时提示先配置，不回退使用服务器共享密钥。
5. 再次保存时密钥留空表示保留；更换接口地址必须重新填密钥。「移除密钥」会删除本账户的模型配置，已经开始的请求仍可能用开始时的配置完成。

密钥在服务端使用 Fernet 加密存入 `user_model_settings` 表，接口不返回明文，浏览器也不存储明文到 localStorage。每次请求创建独立模型客户端，重用检索模型，不修改全局 Agent。来源卡片使用已有翻译缓存，不触发额外的平台翻译调用。

用户提问、相关上下文和检索资料会发送给用户选择的模型服务商；设置页已说明此事及可能产生的 API 费用。

## 部署时必须保留的配置

- `MED_MODEL_KEY_SECRET`：建议单独配置至少 32 字符的随机稳定密钥。未配置时使用现有 JWT 密钥；当前环境已满足加密长度要求。备份数据库时单独备份这把密钥，更改密钥后已有密文无法解密，用户必须重新填写 API Key。
- `MED_USER_MODEL_BASE_URLS`：逗号分隔的 HTTPS 接口地址允许列表，使用完全匹配，用户不能任意填写服务器内网地址。新增服务应由部署管理员确认目的地后加入列表。
- `MED_MAX_CONCURRENT_CHATS=10`：单个后端进程最多同时处理 10 个不同账户的对话。每个账户仍只允许一个运行中请求；第 11 个并发请求返回 HTTP 503 和重试提示。增加多个后端进程时容量会按进程相加，需要另行使用共享容量控制。
- 服务商和模型清单位于 `backend/user/service/UserModelService.py`。这里仅列出当前调用链适配的 OpenAI 兼容 Chat Completions 文本模型；厂商支持新模型后，应先验证 JSON 输出和现有回答评审流程，再加入对应服务商清单。
- 当前清单按 2026-09-11 官方文档整理：OpenCode Go 推荐 `deepseek-v4.1-flash`，DeepSeek 官方推荐 `deepseek-flash`，智谱优先列出 GLM-5.3 系列。DeepSeek 官方旧 Flash 名称不再作为新配置选项。
- 对公网使用 HTTPS，并按已有部署配置启用 `MED_SECURE_COOKIE=true`、配置真实域名与允许来源。
- PostgreSQL 首次启动自动补建个人模型配置表，不改变已有知识库、图谱和检索数据。
- 本次改动发生在 `medical_agentic_rag`，未自动同步 `medical_agentic_rag_upload` 等旧副本；上线时请使用本目录的最新代码与 `frontend/dist`。
- 不要上传 `.env`、`.tools`、本地凭据文件、开发日志或测试报告中的私有数据。生产环境通过安全配置注入必要密钥。

## 用户资料卡片

卡片和导出的引用保留 WHO、NHS 等有用出处、真实外部链接和日期；内部 JSON/JSONL 等文件名统一显示为「医学知识资料」。普通用户接口不包含来源文件路径、行号、召回分数、图路径、分析状态和执行轨迹。历史与 SSE 重放同样过滤；原始管理诊断仍保存在数据库，便于管理员排查自己的运行。
