# 架构与工程取舍

## 原项目基础

保持 FastAPI + Vue、按业务域组织的类式后端。原 `ChatService` 没有调用 RAG，图谱查询允许模型生成 Cypher，向量配置指向网络安全语料，历史保存存在用户归属问题。新版本让问答调用真实检索服务，采用固定只读图查询、服务端保存结果、每条 DAO 查询绑定 owner，并将新数据库与原数据隔离。

原 `LLMService.get_deepseek` 读取 `CHAT_OPENAI_API_KEY`，但 `.env` 使用 `DEEPSEEK_API_KEY`。新 Settings 优先使用已有的 `DEEPSEEK_API_KEY`，兼容旧别名。GLM 的模型名与接口沿用原配置。请求输出模式改为可验证的 JSON；浏览器只收到已经校验的答案与 SSE 动作事件。

## Agent 权限边界

模型的输出始终是候选数据。AgentPolicy 只授予 `rewrite / hyde / stop` 三个反思动作；检索能力来自程序装配的服务，不能指定任意数据库语句、网址、文件、网络请求或写入动作。固定规划确定图谱是否可用，模型可以缩减它，不能越权开启。实体绑定与证据要求不会随模型改写而变化。

当前状态机由显式 Python 类与异步生成器实现，没有额外依赖 LangGraph。它具有有界状态、可观测事件与持久化结果，但不宣称支持跨进程从任意中间模型节点恢复。崩溃后超时运行被标为 interrupted，重新请求需新 request_id。PostgreSQL 是真正的业务数据库，不是仅配置了一个未使用的 PostgresSaver。

工程上分开两种重试：证据不足触发最多 3 轮检索；生成或语义检查失败最多修复 1 次。一次生成与检查最多使用 2 次请求，反思层预留回答预算，总计最多 6 次调用。GLM 负责解释，OpenCode Go 负责受限规划、反思及独立检查。GLM 4.5 与 DeepSeek V4 都显式关闭动态思考以控制响应时间。网络失败时的原文降级明确显示，不冒充完成了自然解释。

## PDF 中采用和修正的设计

- 采用同源疾病图谱、Evidence 结构、混合召回、RRF、可选 HyDE、CrossEncoder、证据和答案双重校验、失败反馈、SSE 与消融评测。
- RRF 保存每个文档各路贡献；同一路重复传入不会重复加分。嵌套融合保留已有贡献，不把已经融合的分数当作新召回路。
- 去重按稳定 source/document ID，保留出处和 graph_paths。相同来源的图谱命中不视作独立医学证据。
- BM25、余弦、CrossEncoder 分数单独保留；排序分数不是经过校准的医学置信度。
- 嵌入与检索共用模型指纹，索引键包含文档 ID、标题与内容，防止维度相同但模型或内容不同的索引混用。QA 导入工具保留为历史实验，服务端默认停用，不属于当前回答数据。
- 假设文本只用于检索，不能成为证据；文献和数据集中的指令不具有执行权限。
- 图谱中没有边不表示药物禁忌，也不能证明安全；特殊人群、剂量、当前指南需要专门证据与专业评估。
- 进程数增加不会天然降低总显存占用，因此默认单服务进程、共享模型和小批量编码。
- LangGraph 本身支持 streaming；项目没有照抄“CompiledStateGraph 缺少 stream”的判断。[官方 streaming 文档](https://docs.langchain.com/oss/python/langgraph/streaming)

## 证据策略与已知边界

权威模式只使用 source_checked 来源，检查出处和核验日期。已知发布日期必须在有效时间范围内；WHO 采集器未能提取发布日期时，必须显式记录 date_provenance 并使用近期核验日期，不能宣称内容是最新指南。source_checked 表示核对公开页面并整理出处，不表示医生审核。新增 8,333 条中英文 WHO 后已核验层为 8,362 条。

探索模式允许 103,008 条历史文档作为研究来源，放松时效与完整分面覆盖要求，标注待复核来源和缺失维度；QA 已停用。来源相关时优先使用已核验资料，历史文档填补缺口。模式由请求参数决定，持久化到 runs，参与 request_id 幂等比较；Agent 无权切换。两种模式都执行急症、个人剂量与特殊人群用药限制。

自然解释采用两级检查。程序先把证据分成带编号的原文片段，模型输出解释及所选编号；程序解析编号并回填原文，检查引用存在、主题和覆盖。独立模型调用再检查解释是否回应问题、是否由引用支持、有无因果倒置或跨人群推广。语义审阅失败最多修复一次。模型审阅会出错，属于工程防线而非医学正确性证明。

主题判断使用明确疾病绑定及症状／指标同义词组，未知实体不获得匹配奖励。概述只匹配概述分面；实体与分面直接召回避免定义被长篇预防资料挤掉。没有明确疾病的症状描述可以检索相关资料，但不会据此建立诊断。短句个人症状询问先补充必要背景。补充的 7 条 NHS／NIDDK 中文摘要有显式来源与核对日期，可在 `data/curated_support.jsonl` 审阅。

证据排序按实体命中优先，再按主题分面覆盖评分，避免高分但不相关的概述（如体力活动指南）压过直接相关的睡眠资料——对应“答非所问／跑题”问题的工程修正。摘要引用按句边界或英文词界截取，保证展示片段是原文完整子串，不再出现句中截断的乱码。英文来源的回复通道在生成提示中要求先用中文讲解并翻译，不再整段照抄英文；来源卡片与知识库界面同时展示中文译文并保留“显示原文”切换，翻译由 `TranslationService` 在线完成并缓存到 `data/translations-cache.jsonl`，任何失败都回退原文，评分始终基于原文引用。

跑题问题的两个工程根因也在证据层修复：相关性评分中“分面匹配”加分不再让宽泛问题（未命中任何分面词、默认概述类，如“晚上总做梦睡不好是正常的吗？”）里任意 overview 文档压过真正的原因/预防资料——宽泛查询对所有分面公平计分；证据门槛的 overview 强制过滤只对定义类问题（含“是什么/什么是/定义”）生效，宽泛问题允许原因/预防/症状等任意分面通过，避免无关概述（如 PTSD 自我护理页里恰好含“睡眠”一词）成为唯一证据。

评测区分相关性、依据与可读性，参考 [Ragas 的指标划分](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/)；项目使用自己的可复现检查与模型审阅，没有宣称运行了 Ragas 官方评分，也没有把路由准确率当成回答正确率。`evaluation/quality_cases.json` 含 28 组普通人就医场景问题（39 条按模式展开），`AnswerQualityRunner --prepare` 只做离线路由校验，`--llm` 用真实模型跑主题/依据/篇幅/综合检查；拒绝回答（abstained）、追问（clarification）与急症（emergency）行的关键词检查按路由类型放宽，避免把正确的拒答误判为失败。

急症识别目前是中英文规则与否定范围处理，并非临床分诊模型；未知表达可能遗漏。测试包含典型表达、否定与转折，不能替代更广泛的人工审查。

四层记忆都按 owner 隔离。L2 读取前用持久层版本核对，所以 Redis 主要减少上下文重复构建，不是免数据库查询的缓存。L3 只恢复当前对话的实体上下文；L4 不把用户主张升级为医学事实。删除对话同步清除 L2 与 L3；L4 需要独立删除，避免误删用户确认偏好。

追问识别覆盖确认与承接语气（“是的，我应该怎么办”“那喝水要注意什么”“应该去看医生吗”），无主语短句从上一轮 L3 实体继承主题，但自带症状/人群词的新问题（“孩子发烧怎么办”）不会被误继承。探索模式抽取回答时优先使用已核验来源，未复核片段含剂量、检查频次或激素建议（prescribing_detail）时整篇隔离，避免一段历史碎片拖垮整条引用校验。

口语化支持：普通人提问（“拉肚子/窜稀/闹肚子”“吃坏东西”“脑壳疼”“晕乎乎”“心慌慌”）经 EXPANSIONS 归一为规范医学词后再检索，腹泻/腹痛/恶心等主题组补充口语同义词（中英）；纯情绪化的模糊主诉（“难受死了”“浑身不舒服也说不上哪疼”）无具体部位时先追问具体症状，避免答非所问或生硬拒答。医学实体匹配对 WHO 文档允许“病/症/炎”后缀（“腹泻”可命中实体“腹泻病”），保证权威模式也能召回对应分面（治疗/预防）文档。

风险分流由 `SafetyRouter` 承担：按“立即急救 / 尽快就医 / 一般 / 澄清”分级并给出稳定原因码，用组合信号规则识别心梗（胸压迫+冷汗+上肢放射）、卒中（面瘫+单侧无力+言语）、儿童脱水（腹泻+无尿+精神差）与阑尾炎样转移痛，同时过滤否定、历史、假设与科普语境；急救与尽快就医提示不依赖向量库、图谱或生成/审核模型。跨轮风险延续把上一轮原文并入路由器再判定（“肚脐疼”→“移到右下腹更疼”升级为 urgent），换话题（自带实体）不误升级。个人用药识别覆盖停药/减量/加量口语（“明天不用吃了吧”“把药停了”“吃一片行不行”），误伤正常饮食问题。

会话事实层由 `ConversationState` + `ContextResolver` 承载：仅用受限规则从用户原话抽取时长（含中文数字“一个月”）、年龄、孕期孕周、描述对象（我/我妈/我爸/孩子）、症状极性（肯定/否定）与纠正；每次请求从 L3 持久化轮次重建，Redis 缺失不丢事实。“我刚才说多久了？”“说的是我还是我妈？”这类纯回忆问题直接从状态回答，不触发检索或模型调用；会话事实与医学证据分离，用户自述永不升级为诊断。

PubMed 作为“最新/今年”问题的补充文献线索接入（`MED_PUBMED_ENABLED` 开启，约 100 项中→英术语白名单）。只在本地语料对最新请求留缺口时检索，文献以 `source_type=research`、`review_status=unreviewed` 进入证据——不伪装已核验；权威模式下仅 `wants_latest` 问题放行且文献不满足个人用药（换药/剂量仍拒答），探索模式同样适用。文献分配到 E 编号后与本地证据一起进入生成上下文，回答可引用其摘要；生成与审核提示要求把文献当作“待专业解读的研究线索”，不得当临床结论。

## 部署与维护范围

默认仅绑定 localhost。Cookie HttpOnly、SameSite Strict，写请求校验 CSRF/Origin；JWT 固定算法、issuer/audience，绑定会话轮换标识，旧登录令牌不能因新登录而复活。账户密码使用 PBKDF2，兼容原 bcrypt 校验。数据库凭据、原 LLM 密钥、OpenCode 密钥不写入状态接口或错误日志。

此版本的并发与限流控制在单进程内，默认接受 10 个不同用户的并发对话；同一账户只允许一个运行中请求。多实例部署需迁移到共享限流、连接池、外部任务队列及版本化数据库迁移。GPU 同步推理在线程中执行并由模型锁保护，HTTP 取消无法强制终止已进入的 CUDA 运算；服务会取消结果输出，但该批运算可能继续到结束。

访客会话过期后无法访问，其数据库行暂不自动删除；账户资料与历史由用户显式删除。正式共享部署前需增加受控保留周期、备份与删除审计，而不是将 Cookie 有效期宣传成数据保留期限。

本地业务数据库、Redis、Neo4j 的连通性验证见 `reports/services.json`。未来若启用 PubMed，仅发送已识别的公共疾病词；目前默认关闭，尚未验证完整联网文献工作流。

OpenCode Go 的模型接口与客户端要求来自 [官方文档](https://opencode.ai/docs/go/)。它主要面向编程 Agent；医学应用长期使用应核实套餐适用性或切换普通 API。客户端标识为 `MediAtlas-Research-Agent/1.0`，会话 ID 使用匿名哈希，未伪装其他客户端。DeepSeek 使用 [官方支持的非思考模式](https://api-docs.deepseek.com/guides/thinking_mode/) 来控制结构化决策输出与耗时。

## 2026-09-08 质量修订

保留宽泛问题的多分面检索，增加题名/实体主题权重，修复同主题相关度升序及重排后的引用编号。LLM 可作自然概括、逻辑衔接、术语解释和审慎的背景追问；禁止无依据的诊断、剂量或因果结论。生成或语义检查失败时停止答案输出，不再以原文摘录绕过校验；离线摘录仅用于明确配置的离线模式。历史条目中的明显伪医学宣称会被候选过滤，源文件和图谱保持原样。

新增 8 条官方中文摘要位于 `data/quality_support.jsonl`，连同之前 7 条合计 15 条；这是针对测试发现的覆盖缺口进行的人工整理，并非全库医学复核。来源支持、独立模型复查、自动测试和人工阅读四者分开记录，不把测试通过等同于临床正确。详见同目录质量审阅报告。
