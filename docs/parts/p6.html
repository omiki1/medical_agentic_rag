10安全工程

这套系统的安全设计贯穿「传输、认证、授权、输入、输出」全链路。它不是为了应付毕设而堆的 checklist，而是有对应测试的、可验证的安全。

10.1 CSRF + Origin 双重校验

backend/common/RequestBoundary.py — 请求边界
async def dispatch(self, request, call_next):
    if request.method in {"POST", "PATCH", "DELETE"}:
        origin = request.headers.get("origin")
        if origin and origin not in self.settings.origins:
            return Response("Origin not allowed", status_code=403)
        length = request.headers.get("content-length", "0")
        if not length.isdigit() or int(length) > 32768:
            return Response("Request too large", status_code=413)
        body = bytearray()
        async for chunk in request.stream():
            body.extend(chunk)
            if len(body) > 32768:
                return Response("Request too large", status_code=413)
    response = await call_next(request)
    response.headers["X-Content-Type-Options"] = "nosniff"
    ...
    if request.url.path not in {"/docs", "/redoc"}:
        response.headers["Content-Security-Policy"] = "default-src 'self'; ..."

注意：请求体大小检查是边读边查（不是先信任 content-length），即使客户端谎报长度，流式读取也会在超限时掐断。

10.2 密码：PBKDF2 + bcrypt 双兼容

backend/common/HashPwdUtil.py（节选）
def hash_password(password):
    salt = secrets.token_bytes(16)
    digest = hashlib.pbkdf2_hmac("sha256", password.encode(), salt, 600_000)
    return "pbkdf2_sha256$600000$" + b64(salt) + "$" + b64(digest)

def verify_password(password, encoded):
    if encoded.startswith("$2"):      # 兼容原项目 bcrypt
        return bcrypt.checkpw(password.encode(), encoded.encode())
    method, iterations, salt, expected = encoded.split("$")
    if int(iterations) > 1_000_000:   # 拒绝异常高迭代 DoS
        return False
    actual = hashlib.pbkdf2_hmac("sha256", password.encode(), b64decode(salt), int(iterations))
    return hmac.compare_digest(actual, b64decode(expected))  # 常数时间比较

12前端：SSE 流式与证据观察台

前端代码量不大（15 个源文件），但有几个值得讲的设计：自研 SSE 解码器、断线重连恢复、以及「证据观察台」这个把系统理念可视化出来的界面。

12.1 自研 SSE 解码器

frontend/src/api/ApiClient.js — SSEDecoder（节选）
export class SSEDecoder {
  constructor() { this.buffer = '' }
  feed(text, final = false) {
    this.buffer += text
    if (this.buffer.length > 2_000_000) throw new Error('服务返回的数据过大')
    const frames = this.buffer.split(/\r?\n\r?\n/)
    this.buffer = frames.pop()
    if (final && this.buffer.trim()) throw new Error('数据流意外中断')
    return frames.flatMap(frame => {
      const data = frame.split(/\r?\n/).filter(l => l.startsWith('data:'))
                        .map(l => l.slice(5).trimStart()).join('\n')
      return data ? [JSON.parse(data)] : []
    })
  }
}

不用 EventSource 而用 fetch + ReadableStream，是因为要支持 POST + 自定义头（CSRF）+ AbortController 取消。解码器按空行分割帧、累积 buffer 处理「半个帧」的情况，是标准 SSE 解析的严谨写法。

12.2 断线重连：结果可恢复

Chat.vue 的 send() 里：如果流中断但已有 savedRunId，会调 GET /api/runs/{id} 把已持久化的结果捞回来。因为后端先持久化 result 再推 done，所以「结果保存」永远先于「流结束」，断线后能精确恢复。
